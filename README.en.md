# Lan House PS5

[Português](README.md) | **English**

![License: AGPL-3.0-or-later](https://img.shields.io/badge/license-AGPL--3.0--or--later-blue) ![Node 24+](https://img.shields.io/badge/node-%3E%3D24-339933) ![Tests: 132 passing](https://img.shields.io/badge/tests-132%20passing-brightgreen)

A website for renting minutes on a PS5 as an auction: each person places a bid (a price for a number of minutes), pays by Pix (the Brazilian instant payment system) and joins the queue; whoever pays more per minute goes first. There is also a free 10-minute queue.

## Overview

Renting a console by the minute is usually handled first-come-first-served or by agreement over WhatsApp, and whoever is willing to pay more has no fair way to move up. Here the rule is public and simple: the queue is ordered by **price per minute**, payment is made upfront by Pix, and a higher bid **never interrupts** the person who is already playing. When nobody paying is waiting, the free queue gets the console.

The project has three parts: the **website** (Node, with accounts, auction, Pix and an owner panel), the **console PC** (an agent that receives the buttons from the site and presses a virtual controller, plus video and sound over WebRTC) and the installation **guides**. The look uses pink, orange and cyan on dark purple (colors only; no logo, name or artwork from any game).

> **Status, plainly:** the site, the auction, the accounts and the panel are done and tested (132 tests). Everything that depends on the real hardware has **never been proven**: the PS5, chiaki-ng and the virtual controller (ViGEmBus) have never run with this system. **Real Mercado Pago and real SMTP e-mail have never been tested** with real credentials; the default Pix is a fake one (`PIX_PROVIDER=mock`). See [Project status](#project-status) and [Before opening to the public](#before-opening-to-the-public).

This repository has no screenshots and no published demo.

## Languages

The site has two complete versions: **Portuguese** at `/` (lan house theme) and **English** at `/en/` (`/en/entrar.html`, `/en/termos.html`, etc.; the file names stay in Portuguese).

- The **PT | EN** switch in the header takes you to the same page in the other language and remembers the choice in the browser. On the first visit, people whose browser is set to English go straight to `/en/`.
- Server messages (errors, notices) and the code e-mails come out in the page language: the browser sends the `x-lang` header (`pt` or `en`; without it, Portuguese).
- The English Terms and Privacy pages are courtesy translations: the Portuguese version prevails and the governing law is Brazilian.
- The owner panel (`/admin.html`) exists in Portuguese only.
- Where the texts live: pages in `site/pages/<id>.html` (pt) and `site/pages/<id>.en.html` (en); header and footer in `site/header.html`/`header.en.html` and `site/footer.html`/`footer.en.html`; JavaScript texts in `public/js/i18n/pt.js` and `en.js` (used with `LH.t('key')`); server messages and e-mails in `server/messages.js`. The tests (`test/i18n.test.js`) check that both languages have the same keys and pages.

## Stack

| Layer | Technology |
|---|---|
| Server | Node 24+, custom HTTP (`server/index.js`), live state over SSE, WebSocket (`ws`) for the button channel |
| Data | Node's built-in SQLite (`node:sqlite`), file at `data/lanhouse.db` |
| Front end | Plain HTML and JavaScript, Tailwind from the CDN, pages generated by `scripts/build.js` from `site/` |
| Pix | `mock` (development) or Mercado Pago (written, never run against the real API); QR drawn in the browser (`qrcode-generator`) |
| E-mail | `nodemailer`: `console` (the code shows up in the log) or `smtp` |
| Video and sound | chiaki-ng (Remote Play) + FFmpeg + MediaMTX, WebRTC (WHIP/WHEP) |
| Virtual controller | Python agent (`host-agent/`): `websockets`, `numpy`, `soundcard`, `vgamepad` (ViGEmBus) |
| Tests | `node --test` (132 tests), `jsqr` to read the QR code back |

## Architecture

```
Player's browser ──HTTPS──► Site server (Node) ◄──heartbeat── PC connected to the PS5
        │                      │  queue, turns, Pix, panel          │
        │                      ▼                                    │ chiaki-ng (Remote Play)
        └──── video + controls (WebRTC and WebSocket) ◄─────────────┘ + virtual controller (ViGEm)
```

1. **Site server** (`server/`): `lanhouse.js` holds the queue rules (pure, tested); `pix.js` has the Pix providers; `accounts.js`, accounts and saved controls; `play.js`, the button channel; `messages.js`, messages and e-mails in pt and en; `index.js`, the API, the panel and the files from `public/`.
2. **Front end** (`site/` generates `public/` with `npm run build`): simple screens, palette defined in `site/head.html`. The account nickname is what shows up in the queue.
3. **Console PC** (`host-agent/`): chiaki-ng shows the PS5 in a window; FFmpeg captures the window and publishes to MediaMTX (WHIP); the agent receives the buttons from the site over WebSocket (`/ws/host`) and presses a virtual DualShock 4, which chiaki-ng relays to the PS5. The browser reads the video over WHEP and sends the buttons over `/ws/play`, only for the player whose turn it is.

Business rules already implemented and tested (details in [`docs/ARQUITETURA.md`](docs/ARQUITETURA.md), written in Portuguese):

- A Pix starts as `pending` and becomes `paid` when the provider confirms; confirmation is **idempotent** and checks the **amount** paid. A Pix paid after its deadline still delivers the time.
- A turn only starts if the console is **online**; if the PS5's PC drops, the purchased time is kept and the player's clock **pauses**.
- The public state never shows e-mail, id or Pix code. The buyer is identified by the session (cookie).
- A bid increase only counts once paid; a price-only increase on a turn that has already started buys nothing and goes to "Refunds to make" in the owner panel.
- The Mercado Pago notification is not trusted by itself: the real status comes from a query to the provider's API.
- Deleting the account anonymizes the nickname in orders and queue entries; the amounts stay for bookkeeping.

## Auction rules (all adjustable in `.env`)

- Bids from 5 to 60 min (in steps of 5), in whole reais, with a floor of **R$ 1.00 per minute** (R$ 10 for 10 min is the lowest bid) and a cap of R$ 200.
- The queue is ordered by **price per minute**; ties go to whoever bid first. A higher bid **never interrupts** the person who is already playing.
- You can **raise your bid** while queued: you pay only the difference and move up. The screen shows where the bid would land before paying and how much is missing to be first.
- **Free queue:** 10 min, one spot per account, 60 min wait between turns of the same account; after 3 paid turns, 1 free turn comes in (`FREE_EVERY=0` = free only when nobody is paying).
- Anyone who is outbid sees a notice on screen. There is no automatic bid refund (the owner can refund manually through Pix).

## Running it

Requires Node 24 or newer.

```powershell
cd lanhouse-ps5
npm install                      # ws and nodemailer (plus jsqr and qrcode-generator, tests only)
Copy-Item .env.example .env      # then edit ADMIN_PASSWORD and HOST_SECRET
npm test                         # 132 tests (auction, free queue, turns, accounts, controls, button channel, languages)
npm run build                    # generates public/*.html from site/
npm start                        # http://localhost:3000
```

With `PIX_PROVIDER=mock` (default) Pix is fake: after generating the Pix a "Simulate payment" button appears. With `MAIL_PROVIDER=console` (default) no e-mail is sent: the confirmation code appears in the terminal where the server runs.

To make the console show as online without the PS5's PC, simulate the heartbeat (every 5 s):

```powershell
curl.exe -X POST http://localhost:3000/api/console/heartbeat -H "x-host-secret: YOUR_HOST_SECRET" -H "Content-Type: application/json" -d "{\"online\":true}"
```

To show the game on the main screen: `WHEP_URL` (low-latency video from the PS5, see the guides below) or, as an alternative, `STREAM_EMBED_URL` (an https "embed" address of a live stream on Kick/Twitch/YouTube). With neither, the page shows "Stream not connected yet".

**Guides** (in Portuguese): [`docs/TESTE-LOCAL.md`](docs/TESTE-LOCAL.md) (test here, without the PS5) and [`docs/INSTALACAO-NO-PS5.md`](docs/INSTALACAO-NO-PS5.md) (install where the PS5 is).

## Install packages

`npm run package` builds two zips in `dist/` (with `SHA256SUMS.txt`), without secrets, databases, `node_modules`, `.venv` or third-party executables:

| Package | Goes to | How to install |
|---|---|---|
| `lanhouse-ps5-host.zip` | the PC next to the PS5 | `instalar.ps1` checks Python and FFmpeg, installs the libraries, downloads MediaMTX **verifying its SHA-256** and creates `config.ps1`; then `iniciar-tudo.ps1`, `parar-tudo.ps1` and `diagnostico.ps1` |
| `lanhouse-ps5-site.zip` | the site server | `instalar-site.ps1` checks Node 24+, installs the dependency and creates `.env` with **random passwords**; then `iniciar-site.ps1` |

The installer was tested in a clean folder: installation, `iniciar-tudo` (video with a test pattern + sound + agent in simulation), the owner panel showing "console PC: ready" and `parar-tudo`. It was not tested with chiaki-ng, the PS5 or the ViGEmBus driver. Each package has a `LEIA-ME.txt` (Portuguese).

## Security of what exists

- Passwords with scrypt and salt; session in an `HttpOnly` + `SameSite=Lax` cookie (only the hash is stored in the database); an `x-lh` header on actions to block requests from other sites.
- Login: 5 wrong passwords lock the account for 15 minutes (the notice says how many attempts remain; the message is the same for an e-mail that does not exist). The lock is stored in the database and survives a server restart. There are also per-IP limits on sign-up, purchase and password change/delete.
- Sign-up: the account only gets in after confirming the e-mail with a 6-digit code (15 min, single use, 5 attempts, 3 codes per hour per e-mail). Someone who gets the password right on an unconfirmed account is sent to the code screen.
- Password reset: 6-digit code (stored only as a hash), valid for 15 minutes, 5 attempts, single use, at most 3 codes per hour per e-mail; the answer is the same whether the account exists or not. When the password changes, all sessions are dropped and the login lock is cleared.
- The owner panel (5 errors) and the console PC secret (10 errors) also lock out for a while.
- When the password changes, the other sessions are dropped. Deleting an account requires the password and is not possible while the person has a queue entry.
- The public state (queue and current player) never shows e-mail, id or Pix code.
- The player never receives the PSN password: they only send buttons through the PC. Use a **PSN account separate** from your main one. The PS button is not relayed, so there is no way to leave the game, switch user or turn off the console from the controller.
- In production use HTTPS and `COOKIE_SECURE=true`. If it sits behind a proxy, the per-IP limits will see the proxy's IP: adjust this before opening to the public.

## Technical decisions

- **No framework and almost no dependencies:** the server uses what Node 24 already ships (`node:sqlite`, `node --test`); only `ws` and `nodemailer` are runtime dependencies.
- **SQLite instead of a database server:** one console, one instance, backup by copying the `data/lanhouse.db` file. Cost: it does not scale to multiple instances.
- **Queue rules as pure code** (`server/lanhouse.js`), comparing integers with no rounding: it can be tested without HTTP and without a real clock.
- **Upfront, idempotent payment:** a repeated webhook does not duplicate the queue entry, and the amount paid is checked.
- **An offline console does not burn purchased time:** the turn only starts with the console PC online, and the clock pauses if it drops.
- **Deliberately limited control:** no PS button, no game switching by the player; only the player whose turn it is sends buttons, and everything is released on turn change, tab close or lost connection.
- **Two languages with a parity test:** `test/i18n.test.js` fails if a key or page is missing in either language.

## Before opening to the public

1. Sony's and the game developers' terms: check whether renting out the console is allowed. Use a separate PSN account.
2. Real Pix: test Mercado Pago with test credentials, then production. Set `PUBLIC_BASE_URL` with HTTPS.
3. Real e-mail: set `MAIL_PROVIDER=smtp` and test sign-up and password recovery with your own e-mail.
4. Change `ADMIN_PASSWORD` and `HOST_SECRET`. The admin panel uses a single password; put the site behind HTTPS.
5. Tailwind comes from the CDN (`cdn.tailwindcss.com`), fine to start with; for production, compile the CSS.
6. LGPD: the site stores e-mail, nickname and purchase history. Have a privacy policy and a way to handle deletion requests (people can already delete their own account).
7. Tax: receiving Pix from many people has tax implications.
8. The 18+ is a checkbox confirmation; there is no age verification.
9. Prove the whole setup with a real PS5 (video, virtual controller, latency and sound) following the acceptance checklist in the installation guide.
